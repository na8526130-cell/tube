# Google Classroom から YouTube Education 埋め込みURLが生成される仕組み

## 概要

Google Classroom 内で YouTube 動画を表示すると、通常の `youtube.com/embed/...` ではなく、次のような YouTube Education 用の URL が利用される場合があります。

```text
https://www.youtubeeducation.com/embed/<VIDEO_ID>?...
```

調査したところ、埋め込みURLに含まれる `rct` や `embed_config.enc` は、ブラウザ側で動画IDから直接計算されているのではなく、**Google Classroom のバックエンドから取得した値**であることが確認できました。

全体の流れは次のとおりです。

```text
YouTube 動画ID
      │
      ▼
Google Classroom の内部 RPC
      │
      ▼
Google サーバー
      │
      ├─ videoId
      ├─ rct
      └─ enc
      │
      ▼
Classroom の JavaScript
      │
      ▼
youtubeeducation.com/embed/... の URL を構築
```

---

## 1. Classroom が動画情報を取得する

Classroom では、動画を表示する際に内部の `batchexecute` エンドポイントへ POST リクエストが送信されます。

RPC ID は次の値でした。

```text
DKRBLb
```

リクエストの中心部分は概念的には以下のようになっています。

```json
[
  [
    [
      "DKRBLb",
      "[\"<VIDEO_ID>\"]",
      null,
      "1"
    ]
  ]
]
```

つまり、サーバーへ渡される主要な情報は YouTube の動画IDです。

例:

```text
<VIDEO_ID>
```

### 注意

実際のリクエストURLやPOSTデータには、次のようなセッション依存・認証関連の値が含まれることがあります。

```text
f.sid
_reqid
at
bl
Cookie
Authorization 相当の情報
```

これらは公開しないでください。

---

## 2. Google サーバーから返ってくる値

`DKRBLb` のレスポンスには、動画タイトル・説明・サムネイルなどに加えて、YouTube Education 用の情報が含まれています。

関連部分を単純化すると、次のような構造です。

```js
[
  "<VIDEO_ID>",
  ["<RCT_TOKEN>"],
  2,
  "<ENC_TOKEN>",
  true,
  null,
  [3, "<INTERNAL_VALUE>"]
]
```

今回確認できた対応関係は次のとおりです。

| 配列位置     | 内容                 |
| -------- | ------------------ |
| `[0]`    | YouTube 動画ID       |
| `[1][0]` | `rct`              |
| `[3]`    | `embed_config.enc` |
| `[2]`    | 用途未確認              |
| `[4]`    | 用途未確認              |
| `[5]`    | 用途未確認              |
| `[6]`    | 内部情報と思われる値         |

重要なのは、

```text
rct
enc
```

の2つが、**すでにGoogleのレスポンス内に存在する**ことです。

したがって、

```text
videoId → JavaScriptでrctを暗号計算
```

という仕組みではありません。

実際には、

```text
videoId
  ↓
Google Classroom Backend
  ↓
rct / enc
```

という流れになっています。

---

## 3. YouTube Education URL の構築

Classroom 側では、取得した値から概ね次のような設定を作成します。

```js
const embedConfig = {
  hideInfoBar: false,
  disableRelatedVideos: true,
  enc: "<ENC_TOKEN>"
};
```

その後、YouTube Education の埋め込みURLへ変換します。

概念的には以下のようなコードになります。

```js
function createYouTubeEducationUrl({
  videoId,
  rct,
  enc
}) {
  const embedConfig = {
    hideInfoBar: false,
    disableRelatedVideos: true,
    enc
  };

  const params = new URLSearchParams({
    enablejsapi: "1",
    rel: "0",
    rct,
    embed_config: JSON.stringify(embedConfig)
  });

  return (
    `https://www.youtubeeducation.com/embed/` +
    `${encodeURIComponent(videoId)}?${params.toString()}`
  );
}
```

生成されるURLは概ね次の形です。

```text
https://www.youtubeeducation.com/embed/<VIDEO_ID>
?enablejsapi=1
&rel=0
&rct=<RCT_TOKEN>
&embed_config=<URL_ENCODED_JSON>
```

実際には1行のURLになります。

# 再現方法

## 方法1: Chrome DevTools で確認する

最も簡単なのは、ログイン済みの Google Classroom 上で実際の通信を確認する方法です。

### 手順

1. Google Classroom を開く
2. Chrome DevTools を開く
3. `Network` タブを開く
4. フィルターに次を入力する

```text
DKRBLb
```

5. Classroom 内で YouTube 動画を表示する
6. 次のようなリクエストを探す

```text
batchexecute?rpcids=DKRBLb
```

7. `Response` を確認する

レスポンス内には、概ね以下のようなデータがあります。

```js
[
  "<VIDEO_ID>",
  ["<RCT_TOKEN>"],
  2,
  "<ENC_TOKEN>",
  true,
  null,
  [...]
]
```

ここから、

```js
const videoId = data[0];
const rct = data[1][0];
const enc = data[3];
```

という形で必要な値を取得できます。

---

## 方法2: Copy as fetch を利用する

DevTools の Network から対象リクエストを右クリックし、

```text
Copy
→ Copy as fetch
```

を選択すると、ブラウザが実際に送信したリクエストを JavaScript として確認できます。

ただし、コピーされたコードには認証情報やセッション固有の値が含まれる可能性があります。

公開時は必ず以下を削除または置き換えてください。

```text
Cookie
at
f.sid
_reqid
SID
gsessionid
個人・学校固有ドメイン
その他の認証トークン
```

公開用コードでは、

```text
<SESSION_VALUE>
<AUTH_TOKEN>
<VIDEO_ID>
```

などのプレースホルダーに置き換えるのが安全です。

# レスポンスの解析

Google の `batchexecute` レスポンスは、通常のJSONだけではなく、先頭に次の文字列が付く場合があります。

```text
)]}'
```

さらに、データサイズを表す数値行とJSONが交互に並びます。

例:

```text
)]}'

1234
[...]

56
[...]

24
[...]
```

`DKRBLb` のデータを取り出す処理は、概念的には次のように実装できます。

```js
function parseDKRBLbResponse(text) {
  text = text.replace(/^\)\]\}'\s*/, "");

  const lines = text
    .split("\n")
    .map(line => line.trim())
    .filter(Boolean);

  for (const line of lines) {
    // データサイズ行を無視
    if (/^\d+$/.test(line)) {
      continue;
    }

    let chunk;

    try {
      chunk = JSON.parse(line);
    } catch {
      continue;
    }

    for (const item of chunk) {
      if (
        Array.isArray(item) &&
        item[0] === "wrb.fr" &&
        item[1] === "DKRBLb"
      ) {
        const payload = JSON.parse(item[2]);

        return payload;
      }
    }
  }

  throw new Error("DKRBLb response not found");
}
```

実際の配列構造はGoogle側の内部実装なので、固定インデックスへ依存する場合は変更に注意する必要があります。

# `rct` と `enc` は何なのか

現時点で確認できているのは、

* `rct` は Google サーバーから返される
* `enc` も Google サーバーから返される
* どちらも通常の人間可読文字列ではない
* Base64 / Base64URL 系の表現に見える
* `rct` は protobuf のような構造を持つ可能性がある
* `rct` と `enc` の内部データには一部共通する特徴がある

という点です。

ただし、

```text
暗号方式
署名方式
各フィールドの正確な意味
```

までは、この通信だけから確定できません。

したがって再現する際には、

```text
rct / enc を自前で生成する
```

のではなく、

```text
Google Classroom から取得した値を利用する
```

という考え方になります。

# まとめ

YouTube Education の埋め込みURL生成は、概ね次の流れです。

```text
1. YouTube 動画IDを取得

2. Classroom が DKRBLb RPC を呼び出す

3. Google サーバーから
   - videoId
   - rct
   - enc
   などを取得

4. Classroom の JavaScript が
   embed_config を作成

5. youtubeeducation.com/embed/<VIDEO_ID>
   のURLを生成
```

最も重要な点は、

```text
rct と enc はブラウザが動画IDから生成しているわけではない
```

ということです。

```text
動画ID
  ↓
Google Backend
  ↓
rct / enc
  ↓
YouTube Education URL
```

という仕組みになっています。

## 注意事項

`DKRBLb` や `batchexecute` は公開APIではなく、Google内部で使用されている実装です。

そのため、

* RPC ID
* 配列構造
* URL
* パラメータ
* レスポンス形式

は予告なく変更される可能性があります。

恒久的なAPIとして利用できることを保証するものではありません。
